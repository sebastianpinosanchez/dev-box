# DevBox agent map

DevBox is a self-hosted React/TypeScript developer toolkit. **No network calls at runtime, ever.** Tool processing is local; local static assets are allowed. Never transmit inputs, secrets, telemetry, or previews. Install/setup is the only network-enabled phase.

## Commands

Use the Node version pinned in `.nvmrc` (`nvm use`).

- Install: `npm ci`
- Develop: `npm run dev` (loopback)
- Test: `npm test`
- Lint: `npm run lint`
- Typecheck: `npm run typecheck`
- Format: `npm run format`
- Build: `npm run build`
- Serve build: `npm start` (127.0.0.1:8080)
- All checks: `npm run verify`
- Browser checks: `npm run test:smoke` (build first; install Chromium during setup with `npx playwright install chromium`)

## Map

- `src/tools/<id>/`: metadata, pure logic, tests, samples, lazy UI entry.
- `src/tools/registry.ts`: automatic discovery; never maintain a second route list.
- `src/components/shared/`: reusable tool and layout components.
- `src/components/ui/`: shadcn vendor components, generated by CLI.
- `src/lib/`: shared types, workers, encoding and safe settings helpers.
- `src/data/`: inert offline reference data.
- `scripts/checks/`: offline, registry, boundary, UI, dependency and vendor integrity checks.
- [Architecture](docs/architecture.md), [conventions](docs/conventions.md), [UI guide](docs/ui-guidelines.md).
- [Decisions](docs/decisions/), [backlog](docs/tool-backlog.md), [dependencies](docs/dependencies.md).

## UI and privacy

Use shadcn components, added through `npx shadcn@latest add <component>`; reuse shared composites. Never hand-edit `src/components/ui/`. Document an unavoidable exception in an ADR. After CLI changes run `node scripts/record-ui.mjs` and review the vendor diff. Keep the Radix `new-york` style in components.json.

No raw styled buttons, inputs, selects, textareas or tables in tools. No alternative UI frameworks. Tool previews must pass the shared sanitizer; never enable remote images, links, scripts, styles or embeds. Use workers for processing, with cancellation and a timeout. Never log inputs or persist inputs/keys/passwords. Only safe options, theme and last route may be saved.

## Adding a tool

1. Read [adding a tool](docs/adding-a-tool.md) and the local AGENTS.md.
2. For a larger change, copy [the plan template](docs/plans/TEMPLATE.md) to a dated plan and keep its progress current.
3. Run `npm run new-tool -- <tool-id> --category "Text"`.
4. Use `src/tools/base64/` as the canonical reference. Replace the scaffold's example logic and tests; do not ship its trim placeholder.
5. Update metadata, sample, UI configuration, tests, backlog and CHANGELOG.md. Registry inclusion is automatic.
6. Document any new dependency with a concrete reason before installing it.

Do not import one tool from another, edit generated checksums manually, or modify unrelated tools while adding one. Shared logic belongs in src/lib; shared UI belongs in src/components/shared. Keep logic framework-free and throw actionable errors. Generated code is text, never executed.

## Definition of done

- Behavior and invalid-input cases covered by meaningful unit tests.
- Accessible labels, keyboard interactions, safe empty/error states and representative sample.
- No sensitive input persistence and no external requests.
- Documentation, dependency justifications, changelog and plan updated.
- `npm run verify` passes; `npm run test:smoke` passes for route/UI changes.
- Report any environment limitation honestly; never claim an unrun check passed.
